# Агент поиска рекламодателей и рекламных площадок

## Цель

MVP для поиска проверенных рекламодателей и Telegram-каналов.
Качество кандидатов важнее количества.

MVP включает:
1. Ядро: валидация, дедупликация, безопасная запись.
2. Первый источник рекламодателей: WB.
3. Telegram-каналы.

Twitch/Kick, остальные источники и OpenAI Agents SDK
подключаются после проверки MVP.

## Окружение

Используется Python 3.11 или новее.

Открой терминал в папке проекта и активируй окружение:

```bash
source .venv/bin/activate
```

Проверка интерпретатора:

```bash
python -c "import sys; print(sys.executable)"
```

Путь должен вести в `.venv/bin/python` внутри проекта.

Сторонние пакеты пока не установлены.
Список зависимостей ведётся в requirements.txt.

## Правила записи

1. Парсеры не записывают данные напрямую.
2. Все изменения проходят через safe_writer.py.
3. Существующие строки целиком не перезаписываются.
4. Заполненные ячейки не изменяются.
5. Агент не заполняет ручные поля автоматически.
6. Контактное лицо и контакты требуют подтверждения человека.
7. Разрешено добавлять строки и заполнять пустые разрешённые поля.
8. Удаление строк и очистка ячеек запрещены.
9. Перед запуском с записью создаётся резервная копия.
10. Изменения записываются в logs/changes_log.csv.
11. При сомнении запись пропускается с предупреждением.
12. По умолчанию используется dry-run.

Настройки в config.py сами по себе не обеспечивают защиту.
Защита реализована в safe_writer.py и проверяется тестами в tests/.

## Ручные поля и история

- Скоринг и новые измерения сохраняются отдельно от основных таблиц.
- Ручной комментарий автоматически не заполняется.
- Статус клиента автоматически не меняется.
- Новые наблюдения не перезаписывают заполненные метрики таблиц.
- Неизвестные значения остаются пустыми.
- Отсутствие данных не считается нулевым значением.

## Готовое ядро: запуск без ИИ

Все команды выполняются из корня проекта с активной .venv.
Сторонние зависимости не нужны.

Безопасная демонстрация (таблицы и журналы не создаются):

```bash
python -m safe_writer --demo --dry-run
```

Проверки защиты на временных файлах:

```bash
python -m unittest discover -s tests -v
```

Для реального кандидата подготовьте JSON-объект с точными названиями
колонок. Числа в JSON должны быть числами, а не строками.
Файл кандидата храните в work/, а не в .venv.

Предварительный просмотр:

```bash
python -m safe_writer --table telegram --input work/candidate.json --dry-run
```

Только после просмотра плана можно явно разрешить запись:

```bash
python -m safe_writer --table telegram --input work/candidate.json --write
```

Подтверждение контактных полей выполняется доверенным CLI:

```bash
python -m safe_writer --table telegram --input work/candidate.json --write --confirm-contacts
```

CLI показывает контакт через repr и требует точный ответ ДА для каждого поля.
Будущая модель не должна получать управление confirmed_fields или флагом
подтверждения. Ручные поля пропускаются даже при добавлении новой строки.
Номер и ID клиента назначает хранилище. Готовность источника и достоверность
контакта эти проверки не доказывают.

## Поведение дедупликации

- Точные ключи сравниваются без изменения исходных значений.
- Отсутствующий ключ требует ручной проверки, а не признания уникальности.
- Несколько совпадений или похожие названия блокируют автоматическую запись.
- Похожесть оценивается нормализованным расстоянием Левенштейна с порогом 0.85.
  Это сигнал оператору, а не автоматическое объединение. Названия длиннее
  256 символов требуют проверки без дорогого расчёта.
- Для бренда без сайта принимается только однозначная публичная TG-ссылка
  в автоматическом поле «Соцсети». Список соцсетей не разбирается автоматически.
- Записи бренда с разными основаниями ключа (сайт / TG) автоматически не связываются.
- Пропущенные поля и причины возвращаются в warnings; при реальной операции
  результат также сохраняется в logs/agent.log.
- Dry-run не пишет даже журналы: план и предупреждения выводятся в терминал.

## CSV, резервные копии и ограничения

Один вызов upsert — одна операция. Перед каждой реальной операцией
создаются снимки всех трёх таблиц в backups/<transaction>/.
Если таблицы ещё нет, её снимок содержит только согласованный заголовок.
Существующие файлы копируются в бэкап побайтно.

CSV не имеет форматирования, выпадающих списков или вычисляемых формул.
Существующий текст ячеек, включая формулы, сохраняется как текст.
Адаптер Excel / Google Sheets ещё не реализован.

Обновление ячейки CSV технически сохраняет файл целиком через временный
файл и атомарную замену. Порядок строк и колонок и значения остальных
ячеек сохраняются; оформление CSV (кавычки, переводы строк) может измениться.

На время реальной записи закройте CSV в программах редактирования.
.safe_writer.lock блокирует другие экземпляры нашего писателя, но не Excel
и сторонние программы. Повторное сравнение файла обнаруживает изменения
до замены, однако абсолютной защиты от внешней одновременной записи нет.

ERR принимается в диапазоне 0–100; превышение требует проверки.
Средний охват и онлайн пока принимаются только целыми по согласованному
правилу. Цены должны быть конечными неотрицательными числами; даты обновления
— ISO 8601 с часовым поясом. Проверка URL не подтверждает доступность сайта.
Скоринг WB реализован в отчётах источника, отдельно от ручного комментария.
История метрик в отдельной таблице, feedback и расписание пока не реализованы.

## Восстановление после сбоя

changes_log.csv содержит transaction, time_utc, state, table, number,
field, before, after, reason. Значения state:
- prepared: план записан в журнал до изменения таблицы;
- committed: изменение таблицы завершено;
- aborted: изменение отменено из-за обнаруженного конфликта.

Если запись таблицы или завершающего журнала прервалась, последующие записи
блокируются. Не запускайте запись повторно вслепую:

1. Убедитесь, что процесс писателя завершился. При оставшейся блокировке
   проверьте PID внутри .safe_writer.lock; не удаляйте блокировку активного процесса.
2. Сохраните дополнительные копии текущих данных и журналов.
3. Найдите незавершённую transaction в changes_log.csv, сравните таблицу
   с соответствующим backups/<transaction>/ и планом before/after.
4. Согласуйте восстановление с оператором. Автоматического отката нет:
   он мог бы затереть ручные изменения. Для разблокировки потребуется
   проверенное завершение состояния транзакции, а не очистка журнала.

Не редактируйте файлы данных и журналов до разбора ситуации.

## Оркестратор agent.py

Демонстрация четырёх кандидатов без записи:

```bash
python -m agent --demo --dry-run
```

На пустом хранилище результат: одна запланированная новая строка,
одно заполнение пустой ячейки этой строки, один отклонённый кандидат
с отрицательным числом подписчиков и один пропуск из-за отсутствия ключа.
Кандидаты вымышлены, сеть не используется. Демонстрационный запуск
возвращает код 2, потому что намеренно содержит ошибочного кандидата.
Если в таблицах уже есть данные, итог может отличаться.

Пакетный ввод отличается от safe_writer: нужен JSON-массив объектов,
а не один объект. Пример содержимого work/candidates.json:

```json
[
  {
    "Название": "Пример канала",
    "Ссылка": "https://t.me/example_channel",
    "Подписчики": 1000,
    "Средний охват": 250,
    "ERR (%)": 25.0
  }
]
```

Это только образец формата, не проверенная площадка.
Файл автоматически не создаётся.

Предварительный просмотр:

```bash
python -m agent --table telegram --input work/candidates.json --dry-run
```

Реальная запись после проверки собственных кандидатов:

```bash
python -m agent --table telegram --input work/candidates.json --write
```

Без --write всегда используется dry-run. Параметры --write и --dry-run
взаимоисключающие; --demo с --write запрещён.

Dry-run хранит планируемые таблицы в памяти, поэтому учитывает предыдущих
кандидатов в пакете. Рабочие таблицы, бэкапы и журналы не меняются.
Номера и ID в плане предварительные: при реальном запуске они могут отличаться.
Внутренний _PreviewWriter использует существующий планировщик SafeWriter._plan,
чтобы повторно не реализовывать правила защиты. При изменении хранилища
пакетные тесты нужно запускать вместе с тестами писателя.

Итоговый JSON содержит dry_run, status, results и summary:
- total / processed / remaining — размер списка, обработано, осталось;
- added / updated — выполненные операции или план при dry-run;
- skipped — нет изменений либо нужна проверка, причина в warnings;
- rejected — некорректные кандидаты, причина в reason;
- failed — операция остановилась из-за сбоя хранилища.

Счётчики отражают операции над кандидатами, а не число уникальных строк.
Одна строка может сначала добавиться, затем дополниться следующим кандидатом.
При сбое операция могла завершить запись до ошибки журнала, поэтому она
помечается failed, а не считается гарантированно выполненной или отменённой.
Предыдущие операции не откатываются. При status=stopped проверьте журнал
и бэкапы по инструкции восстановления до следующей записи.

Коды возврата: 0 — завершено без отклонённых кандидатов, 1 — сбой запуска
или хранилища, 2 — есть отклонённые кандидаты либо ошибка аргументов CLI.
Пропуски с предупреждениями сами по себе не меняют код 0; проверяйте JSON.

agent.py не подтверждает контакты: они пропускаются с предупреждением.
Для подтверждения отдельной записи используется доверенный CLI safe_writer
с --confirm-contacts. Подтверждения из JSON не принимаются.
Проверки формата не подтверждают качество бренда или достоверность метрик:
проверка источников, enrichment и скоринг будут отдельными этапами.


## MVP: состояние и границы проверки

Реализованы источники WB и TGStat, импорт выгрузок, фильтры качества,
обогащение заданных сайтов, география только РФ/Беларусь, защищённая запись.
Это не подтверждение работоспособности живого сбора: при проверке WB вернул
HTTP 403, robots.txt также оказался недоступен; токена TGStat у оператора нет.
Обход блокировок, автоматическая регистрация аккаунтов и покупка API не выполняются.

Без аккаунтов доступна проверка всего пути на явно синтетических фикстурах:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m agent --source wb --wb-file tests/fixtures/wb_catalog.json --brand-proofs tests/fixtures/brand_proofs.json --dry-run
python -m agent --source tgstat --tg-file tests/fixtures/tgstat_channels.json --dry-run
```

Фикстуры — вымышленные данные, а не найденные клиенты. CLI запрещает
--write для выгрузки с synthetic=true. Не снимайте этот признак для записи
примеров в рабочие таблицы. Даты фикстур фиксированы: спустя 30 дней отбор
правильно потребует перепроверку. Автотесты используют свежие временные даты.

На дату подготовки WB-пример даёт accept=1 / review=1 / reject=1;
Telegram-пример accept=2 / review=1. Результат dry-run — план, не реальная запись.
WB-пример возвращает код 2 из-за намеренного отказа кандидату источником.

## Настройка реального Telegram

Токен хранится только локально в .env, не в командах и не в чате:

```dotenv
TGSTAT_API_TOKEN=
```

Вставьте значение после знака =. Уже заданные переменные окружения имеют
приоритет над .env. Поиск /channels/search требует API Stat S или выше;
получение статистики доступно на всех тарифах API Stat. Проверяйте доступ
и квоту в своём аккаунте; проект не покупает тариф автоматически.

```bash
python -m agent --source tgstat --query игры --countries ru by --limit 10 --dry-run
```

Затем, после просмотра результатов, замените --dry-run на --write.
Задержки 2–5 секунд, максимум 120 запросов за сбор, не более 3 попыток
временных сетевых/серверных ошибок. 401/403/429/498 останавливают сбор без
обхода защиты; TLS-проверка включена. Даже dry-run сетевого источника
использует API-квоту; он запрещает локальную запись, а не сетевые запросы.

Фильтры Telegram:

```bash
python -m agent --source tgstat --query игры --countries ru by --limit 10 --min-subscribers 1000 --min-reach 300 --min-err 5 --max-err 80 --dry-run
```

--category принимает код категории TGStat, не произвольную строку тематики.
Ищем обе выбранные страны с распределением лимита, если лимит позволяет.
Проверяем ID и username между info/stat, страну из info, ограничения TGStat,
дату измерения и метрики. Тематика берётся из category ответа get, не из запроса.
Цены не выводятся из охвата. Найденные в описании контакты — только предложения.
Признак RU/BY здесь — география канала по TGStat, не доказательство состава аудитории.

## Импорт разрешённых данных Telegram без API

Создайте собственный JSON с объектом channels. Каждая запись содержит:
- info: ответ channels/get (можно с оболочкой status/response);
- stat: ответ channels/stat;
- observed_at: фактическое время получения метрик ISO 8601 с часовым поясом.

Формат показан в tests/fixtures/tgstat_channels.json. Используйте собственную
разрешённую выгрузку; наличие синтетического примера не даёт реальных данных.

```bash
python -m agent --source tgstat --tg-file work/my_channels.json --dry-run
```

Страны без подтверждения, приватные приглашения, чаты и неоднозначные
идентификаторы направляются на проверку. ERR выше 100 не обрезается.

## WB: получение и обогащение кандидатов

Стандартный Seller API не считаем поиском произвольных чужих брендов.
Неофициальный поиск экспериментальный, выключен по умолчанию. Явный запуск:

```bash
python -m agent --source wb --query косметика --countries ru by --limit 20 --allow-unofficial-wb --dry-run
```

Перед запросом проверяется robots.txt. Если он недоступен или запрещает
запрос, сбор останавливается. Endpoint задан в config.py, может измениться;
живой положительный ответ в этой среде не получен. Браузер, CAPTCHA и
ротация аккаунтов не используются.

Резервный путь — сохранённый разрешённый JSON-каталог с products или
с data.products. Для товара используются brand, name, reviewRating, feedbacks.
Лучший по порогам товар выбирается до удаления повторов бренда.

```bash
python -m agent --source wb --wb-file work/my_wb.json --brand-proofs work/my_brand_proofs.json --countries ru by --dry-run
```

Карта доказательств индексируется названием бренда в нижнем регистре.
Образец структуры находится в tests/fixtures/brand_proofs.json. Каждый факт:

```json
{
  "value": "Россия",
  "url": "https://example.com/company",
  "checked_at": "2026-10-17T12:00:00+03:00",
  "operator_verified": true
}
```

Это формат, не настоящее доказательство. operator_verified=true разрешено
ставить только после проверки оператором. Будущая LLM не должна создавать
этот признак самостоятельно. Подтверждение должно быть не старше 30 дней.

Поля доказательств: brand, country, website, instagram, telegram, youtube,
contact, last_activity, advertising, niche, agency, account_age_days, followers,
micro_niche. value у last_activity — ISO-дата с часовым поясом; у advertising,
agency, micro_niche — bool; возраст и подписчики — целые числа.

Страна бренда требует самостоятельного доказательства: выдача WB,
язык сайта, валюта и регион доставки его не заменяют. Все ниши допустимы;
--niche добавляет фильтр и баллы только при подтверждённом совпадении.
Целевая аудитория, бюджет, контактное лицо и рекламный формат не угадываются.

Скоринг: сайт +15, IG +10, TG +10, YouTube +5, недавняя активность +15,
контакт +20, совпадение заданной ниши +15, рекламные размещения +10.
Скор и причины хранятся в отчёте; при --write отчёт сохраняется в agent.log.
Ручные «Комментарий» и «Telegram/почта» не заполняются.
Без сайта, контакта, недавней активности, социальных страниц или
подтверждённого возраста/подписчиков решение требует проверки.
Агентства, молодые аккаунты и маленькие аудитории без микроисключения
отклоняются. Неизвестное значение не считается ложным или нулём.

Дополнительная живая проверка заданных сайтов:

```bash
python -m agent --source wb --wb-file work/my_wb.json --brand-proofs work/my_brand_proofs.json --enrich-sites --dry-run
```

Проверяются robots.txt, публичность адреса, наличие названия бренда на странице.
Предлагаются публичные ссылки на соцсети и контакты. Предложения автоматически
не становятся доказательствами оператора и не попадают в ручные поля.
Перенаправления отключены; если robots.txt недоступен, проверка останавливается.
Проверка DNS ограничивает локальные адреса, но transport с DNS pinning
не реализован: не подавайте на обогащение недоверенные адреса из произвольного LLM.

## Интерпретация отчёта источника

source_summary.accept/review/reject — отбор источника. Только accept
передаётся в safe_writer. summary описывает последующие операции хранилища.
results содержит source_index, связывающий запись с решением источника.
Контрактные тесты используют httpx.MockTransport, а не реальные API.
В отчёте явно указан режим live/import. Любой источник может вернуть
пустой список — это не доказательство отсутствия рекламодателей.
Ошибки сети/токена выводятся без URL-параметров и ответа с секретами.

## Браузерный TGStat без API-токена

Добавлен источник tgstat-web в существующий tg_parser.py. Он читает видимые
карточки сайта через Playwright, используя обычный Chromium без stealth,
экспорта cookies, личного профиля или перехвата API-запросов.

Важно: пункт 5.1.1 соглашения TGStat запрещает автоматизированный сбор через
веб-интерфейс. Оператор отдельно разрешил использовать этот способ несмотря
на риск ограничения аккаунта. Это не разрешение от самого TGStat. Обход
CAPTCHA, платных блоков, 403/429 или других ограничений не реализован.

В текущем окружении Playwright и Chromium уже установлены. На новой машине:

```bash
python -m pip install -r requirements.txt
PLAYWRIGHT_BROWSERS_PATH=cache/ms-playwright python -m playwright install chromium
```

Обработка конкретных каналов:

```bash
python -m agent --source tgstat-web --channels @exploitex @kod_ru https://by.tgstat.com/channel/@devby --limit 3 --dry-run
```

Откроется отдельное окно Chromium. Войдите в TGStat самостоятельно кнопкой
на сайте. Не вводите пароли, номера или коды входа в терминал/чат. Когда вход
завершён, вернитесь в терминал и нажмите Enter. Сборщик вернётся на карточку,
проверит вход и прочитает метрики. Затем окно закроется.

Сессия временная: авторизация не сохраняется между запусками. Сессия
встроенного браузера Codex не переносится. Сохранение сессии можно добавить
отдельно по явному запросу оператора, с учётом хранения секретов.

Подбор по каталогу выбранной категории:

```bash
python -m agent --source tgstat-web --category tech --countries ru by --limit 4 --min-subscribers 1000 --min-reach 100 --dry-run
```

category в браузерном режиме — slug страницы каталога, например tech,
beauty или business. Это отличается от кодов категорий API TGStat.
--query в этом режиме не поддерживается: используйте категорию или прямые
адреса. На первом экране выбираются видимые карточки, без пагинации;
это небольшая выборка, а не поиск по всему каталогу. Сначала применяется
лимит просмотра, затем фильтры качества: принято может быть меньше лимита.

По умолчанию до 5 каналов, максимум 10; задержки между переходами 2–5 секунд.
Для записи после просмотра плана замените --dry-run на --write.
Повторный запуск снова потребует входа. Даже при --write данные не пишутся
до завершения сбора всех карточек. Пакетные операции хранилища по-прежнему
не являются одной общей транзакцией.

Подписчики и средний охват извлекаются из отдельных видимых карточек h2.
Средний рекламный охват и просмотры Stories не подменяют средний охват поста.
Сокращения вроде 2k не превращаются в точные числа. При конфликте показателей,
неизвестной стране или пропавших метриках запись направляется на проверку.
ERR рассчитывается по согласованной формуле, а не копируется из другого
блока сайта. Контакты — только предложения оператору, цены не угадываются.
Полный текст страницы и имя вошедшего аккаунта в отчёт не сохраняются.

Веб-адаптер не подделывает формат API и его внутренние ID. При импорте
снимка используется объект captures с полями url, title, text, metrics,
observed_at; metrics — массив объектов value/label, observed_at — ISO 8601
с часовым поясом. Запуск импорта без браузера:

```bash
python -m agent --source tgstat-web --web-file work/web_capture.json --dry-run
```

Извлечение двух карточек метрик проверено на живой авторизованной странице
@devby во встроенном браузере. Полный отдельный Chromium-проход с ручным
входом ещё требует проверки оператором. API-адаптер и старые команды сохранены.

## Качество Telegram: предложение рекламного размещения

Теперь одного прохождения фильтров метрик недостаточно для source accept.
В браузерном режиме проверяется верхняя часть карточки до раздела «Сводная»;
в API — описание about. Нужна явная рекламная подпись рядом с публичным
Telegram-контактом либо почтой, например «Реклама: @manager» или
«По вопросам рекламы: ads@example.com». Контакт может быть на следующей
строке, но редакционный контакт или поддержка не подставляются вместо него.

Результат включает placement со статусом offered/unconfirmed/not_offered,
контактами-предложениями и короткими фрагментами доказательства. Это поля
отчёта, не новые колонки таблицы. Никакой автоматической записи контактов нет.

Сотрудничество без явного предложения рекламы, обычное упоминание рекламы,
рекламные охваты в статистике, отсутствие контакта или явный отказ от рекламы
оставляют площадку на review. Хорошие метрики при этом остаются в candidate
для проверки оператором. Слабые метрики продолжают давать reject независимо
от рекламной подписи. Ручного подтверждения рекламного предложения через CLI
пока нет: оператор может отдельно проверить площадку, но адаптер сам не
ставит признак подтверждения.

Корпоративный статус или название компании не являются автоматическим
отказом. Такой канал принимается по тем же признакам предложения, что и
другие. Правило эвристическое: оно не доказывает актуальность прайса,
личность менеджера, готовность принять конкретный бренд или отсутствие накрутки.
Продажная цена не извлекается и не угадывается.

Изменение применяется только к новым запускам источников. Существующие
строки, ручные поля, схемы таблиц и старые журналы не меняются. Исторические
примеры отчётов могли давать accept по метрикам без нового критерия; их
нельзя считать подтверждёнными рекламными площадками без перепроверки.
Режим --input остаётся доверенным ручным импортом через защиту писателя,
а не заменой качества source-адаптера.

## Подбор из основного списка категории

В браузерном режиме --category ссылки выбираются только внутри формы
#category-list-form. Витрины верифицированных каналов, тематические подборки,
популярные посты и рекламные блоки вне неё не используются.
Отсутствие или неоднозначность формы останавливает подбор; поиска ссылок
по всей странице в качестве резервного пути нет.

Сохраняются порядок основного списка, выбранные страны и лимит просмотра
(по умолчанию 5, максимум 10). До открытия карточек исключаются повторы
по username, включая ссылки на один канал с разных доменов TGStat.
Чаты, отдельные публикации и закрытые приглашения не входят в выборку.
При этом каналы, уже сохранённые в CSV, могут повторно читаться: их
дедупликация и заполнение пустых разрешённых полей остаются за safe_writer.

Основной список — порядок каталога TGStat, не наша рекомендация по качеству.
Наличие канала в нём не подтверждает продажу рекламы или отсутствие накрутки.
После чтения карточки по-прежнему применяются география, метрики и критерий
явного рекламного предложения; принято может быть меньше лимита.
Пагинация и автоматическое увеличение объёма чтения не добавлены.

Команда остаётся прежней:

```bash
python -m agent --source tgstat-web --category tech --countries ru --limit 4 --dry-run
```

Селектор основной формы и её ссылки проверены в живом каталоге. Граничные
случаи, исключение дублей и отсутствие резервного поиска проверены тестами.
Это не повторная проверка локального ручного входа: она требует оператора.

### Браузерный режим остальных платформ

Дополнительно доступны `wb-web`, `ozon-web`, `instagram-web`, `youtube-web`,
`twitch-web`, `kick-web`. Вместе с `tgstat-web` это семь браузерных источников.
Новые источники принимают **прямые ссылки** через `--urls`, максимум 10 страниц.
Автоматический поиск по каталогам реализован только для TGStat; остальные
источники пока не ищут профили самостоятельно. Платные API не требуются.

Пример (замените ссылку на нужный реальный профиль):

```sh
python -m agent --source twitch-web --urls https://www.twitch.tv/USERNAME --countries ru by --limit 1 --dry-run
```

Для каждого адреса открывается отдельная страница во временном Chromium.
Войдите самостоятельно, откройте нужные сведения и нажмите Enter в терминале.
Сборщик читает видимый текст. Он не сохраняет сессию, не вызывает внутренние
API, не обходит CAPTCHA и ограничения доступа. При ошибке частичный пакет
остаётся только в предварительном просмотре, даже с `--write`.

WB/Ozon/Instagram/YouTube направляют подтверждённые бренды в таблицу
рекламодателей; Twitch/Kick — в таблицу стримеров. YouTube-канал или продавец
маркетплейса автоматически не объявляется рекламодателем. Исторические средний
и пиковый онлайн заполняются только при однозначной явной подписи с полным
целым числом. Текущий онлайн не используется вместо среднего.

Страна ru/by требует проверенного факта оператора. Файл для `--brand-proofs`
содержит объект с ключами — точными нормализованными ссылками без завершающего
слеша. Каждый факт имеет `value`, `url` источника, `checked_at` с часовым поясом
и `operator_verified: true`. Не ставьте подтверждение неподтверждённым данным.
Для стримера необходим `country` и видимое рекламное предложение с контактом.
Для бренда нужны факты из существующей модели качества: `brand`, `country`,
`website`, социальные страницы `instagram`/`telegram`/`youtube`, `contact`,
`last_activity`, `account_age_days`, `followers`; при необходимости `niche`,
`advertising`, `micro_niche`, `agency`. Источник факта `brand` должен совпадать
с открываемой страницей, а название присутствовать в её тексте. WB/Ozon также
требуют `rating` и `reviews` (пороги существующего WB-фильтра).

Без этих подтверждений результат `review` ожидаем: запись не происходит.
Контакты остаются предложениями, ручные поля не заполняются. Сами факты
проверки не являются командой на запись контакта.

Офлайн-проверка поддерживает `--web-file`: JSON-объект с массивом `captures`,
где каждый элемент имеет `url`, `title`, видимый `text`, `observed_at` с часовым
поясом. Снимки старше суток отправляются на проверку. Флаг `synthetic: true`
на верхнем уровне запрещает запись тестового файла в рабочие таблицы.

Статус: контракты, отбор и безопасная запись проверены локальными тестами.
Живой вход и соответствие DOM каждого из шести новых сайтов ещё требуют
проверки оператором. Это режим чтения прямых страниц, не готовый автономный
поиск по всем платформам и не подключение LLM.


### Автоматический обход Twitch/Kick

```sh
python -m agent --source twitch-web --discover --countries ru by --limit 4 --dry-run
python -m agent --source kick-web --discover --countries ru by --limit 4 --dry-run
```

Эти команды сами выбирают ссылки из видимых карточек публичного каталога,
убирают повторы и читают профили. Неподтверждённая страна/рекламное предложение
оставляют кандидата на проверке. Автопоиск ограничен первой загруженной порцией
карточек, без прокрутки всех страниц и обхода лимитов сайта.

Для шести новых браузерных режимов паузы на каждой странице теперь отключены.
Если страница требует входа, обычный запуск останавливается с понятной ошибкой.
Флаг `--interactive-login` разрешает паузу для ручного входа при необходимости
в интерактивном терминале; кнопка «Войти» в шапке открытой страницы паузу не
вызывает. TGStat пока сохраняет прежнюю процедуру входа.

Для Twitch/Kick уточнены области чтения профиля и форматы точного числа
фолловеров. Чат внутри выбранной области блокирует сбор. Страна из явной
подписи `Страна:`/`Country:` может использоваться автоматически; язык
трансляции не используется как страна. Противоречия требуют проверки.

Живая проверка через встроенный браузер подтвердила карточки каталогов и
разметку профилей Nix (Twitch) и Fijek (Kick). Это не сквозная проверка локального
Chromium: поведение отдельного Playwright проверяется дополнительно тестами
с заменой браузера. Новые режимы WB/Ozon/Instagram/YouTube ещё требуют живой
проверки. Рабочие CSV в этой доработке не менялись.

### Проверка WB/Ozon/YouTube и расширение автопоиска

```sh
python -m agent --source wb-web --discover --countries ru by --limit 4 --dry-run
python -m agent --source ozon-web --discover --countries ru by --limit 4 --dry-run
```

Для WB/Ozon сборщик берёт карточки первой загруженной порции главной страницы.
Это поиск начальных кандидатов, без гарантии ниши и страны бренда. Дополнительные
подтверждения качества требуются по прежним правилам. Метрики товара из видимой
карточки могут использоваться вместо ручных фактов `rating`/`reviews`; при
противоречии с проверенными фактами кандидат остаётся на проверке.

У Ozon читаются отдельные блоки названия и рейтинга: элемент main отсутствует.
У WB название берётся из блока productTitle, а не h1 с рейтингом; отзывы
покупателей и рекомендации не включаются в текст товара. Известные служебные
параметры ссылок нормализуются: WB `targetUrl`, Ozon `sh`, `at`, `__rr`,
`abt_att`. Другие параметры блокируются, чтобы не смешивать разные товары.

У YouTube читается только заголовок канала yt-page-header-renderer, который
может находиться вне main. Это не поиск рекламодателей по интеграциям — такой
поиск ещё предстоит реализовать. Instagram без авторизации показывает форму
входа; чтение его реальных профилей в текущей проверке не выполнено.

На живых страницах встроенного браузера проверены карточки каталогов WB/Ozon,
товар WB 16001947, товар Ozon 585979289 и заголовок канала YouTube NAKEDBOOTS.
Сборщики отдельных Chromium-сессий всё ещё требуют сквозного живого запуска:
вход, задержки и доступность данных могут отличаться. 121 локальный тест проходит.
